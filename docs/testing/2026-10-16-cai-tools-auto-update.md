## 已实现的行为

更新链路为：关于页 → UpdaterAPI → WindowsPlatformUpdater → ElectronUpdaterService → 自有 GitHub Releases → NSIS。

- 固定使用公开的 `Caicy/CAI.Tools` 和 `local` 通道，拒绝替代 generic feed、上游更新与降级。客户端不含 GitHub Token。
- 安装版启动及每 30 分钟检查一次，可在关于页关闭。发现更新后提示，用户决定下载、取消、重试和安装；不在普通退出时静默安装。
- 复用 electron-updater 的差分下载、完整包回退、进度、取消、缓存和完整性校验。并发检查合并，检查不能覆盖下载或安装状态。
- 下载失败可重试；取消后不安装；安装启动抛错或进程仍存活时收到安装错误，恢复退出标志并保留已下载状态。初始化失败明确显示错误。
- 保持 `tools.cai.local`、`CAI.Tools`、默认 `~/.cai-tools`、设备/账户 LMDB 及插件目录。只修正安装兼容标记中残留的上游 appId，没有更换应用身份或迁移数据库。
- NSIS 保留 `deleteAppDataOnUninstall: false`，使用原安装目录；退出仍通过原合同关闭 LMDB。
- Windows ZIP 保持手动安装边界，不能直接在软件内替换便携目录。macOS 来源识别已统一，但未做 macOS/Linux 安装验收。

## 真实 Windows 安装验收

[成功运行 38847310150](https://github.com/Caicy/CAI.Tools/actions/runs/38847310150)，验收脚本提交为 `af7783f4f408295dc39269e60f33e54a962d34e0`。机器可读结果见 [2026-10-16-windows-upgrade-result.json](2026-10-16-windows-upgrade-result.json)。Actions 制品 `CAI.Tools-windows-upgrade-evidence`（ID `12024116380`）包含原始报告和更新窗口截图。

验收在 GitHub 托管的一次性 Windows VM 中执行，脚本拒绝日常电脑和自托管 runner。安装目录位于 RUNNER_TEMP，数据根为该临时 VM 全新测试账户的默认 `C:\Users\runneradmin\.cai-tools`；执行前要求此根不存在。没有在用户日常 Windows 账户下安装测试包。源码 `pnpm test:e2e` 保持临时目录和开发方式，实装验收直接下载已发布安装器，不另行打包。

实际完成的步骤：

1. 匿名下载 local.4 的完整 NSIS 安装器，并与发布的 SHA256SUMS 比对。实际为 95,348,121 字节，SHA256 为 `81664c12e00118649273493d909f3793bfa1323e4c36267fae2956bd7bbb6091`。
2. 静默执行完整安装器，确认 NSIS 标记存在，实际安装版报告 local.4，且不是源码开发实例。
3. 写入宿主主题、自动检查偏好与哨兵设置；安装第三方开发验收插件，写入插件 LMDB 文档、dbStorage 与二进制附件。
4. 在实际应用中通过真实 GitHub 更新源检查到 local.5，显示发布说明和“下载并安装”按钮。没有替换更新器、下载事件或安装 API。
5. 开始真实下载并取消，确认 local.4 仍在运行且可重新下载。
6. 重试后完成真实差分下载。日志记录完整包约 93,113 KB，实际差分下载约 914 KB（日志显示 1%）。
7. 软件内启动 NSIS 安装；观察旧进程退出、原目录应用包变为 local.5、新进程自动启动。
8. 观察自动启动后结束临时测试进程，再以调试连接打开实际安装版进行确定性回读：版本为 local.5，安装目录、数据根、选定宿主设置、插件注册、插件文档、dbStorage、附件字节及旧目录哨兵均保留。
9. 再次向真实更新源检查，未提示同版本更新。

此结果覆盖测试账户的默认路径和所用插件夹具，不代表所有第三方插件、企业策略或所有 Windows 版本均已验收。自动检查定时器通过单元测试，实装验收主动调用检查，没有等待 30 分钟定时器。

## 失败记录与剩余限制

- 首次发布 CI 因 Electron 安装钩子未执行，以及 `RUNNER~1` 短路径别名被安全检查拒绝而失败。通过显式准备固定版本 Electron、规范测试临时路径修复；未放宽产品路径边界。后续两版发布均通过。
- 首次实装验收使用仅对父进程设置的自定义 `ZTOOLS_DATA_ROOT`。真实升级、自动启动及使用原环境重新打开后的数据回读成功，但默认目录被自动启动进程创建，严格隔离断言失败。NSIS 的 `ExecShellAsUser` 通过 Windows Shell 启动程序，不继承这类临时进程变量。数据没有被删除，但自动启动会使用默认根。使用此模式应以原环境手动重启；本次未修复此限制。
- 默认根验收是在另一台全新的临时 VM 中独立通过的，没有将上述失败改报为通过。
- SmartScreen/签名提示、企业防护与杀软、提权取消、断电/安装中断没有现场验证。旧进程退出后的安装失败不能保证由旧窗口显示，也没有自动回滚。
- 当前只接收 `local` 通道；正式版通道切换、macOS/Linux 安装流程未验收。GitHub 可达性仍依赖用户网络，没有新增付费源。
- 旧 local.1～local.3 未启用应用内下载安装，必须先手动安装启用更新的完整版本。普通用户可直接安装 local.5，后续更高 local 版本走软件内更新；本次实际验证的升级对为 local.4→local.5。
