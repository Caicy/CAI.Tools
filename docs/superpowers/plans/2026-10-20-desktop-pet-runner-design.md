# 小薄荷 · 桌面快跑模式设计

原始设计：2026-10-20；渐进难度与设备拖动更新：2026-10-21，按已确认方案实施。当前测试结论见 `tests/desktop-pet-runner-report.md`。第 9 节保留首版历史验收。

## 1. 产品方向

给现有小薄荷增加类似恐龙快跑的单键跳跃玩法：主动进入后，小薄荷来到桌面底部的短跑道，自动向前跑，玩家跳过障碍，碰撞结算，随时返回桌宠。主角继续使用小薄荷；“恐龙快跑”指玩法，不要求把宠物换成恐龙。

目标是一局几十秒到几分钟的休息游戏。默认不自动启动、不持续跑动；退出后恢复现有静态待机与鼠标凝视。

## 2. 入口与完整流程

1. 右键宠物 →「开始桌面快跑」。仅有效宠物模式提供入口。
2. 在宠物所在显示器底部、任务栏上方展开跑道。加载成功后临时隐藏原宠物，显示同一个角色在跑道左侧。
3. 准备画面显示「空格 / 点击跑道：跳跃」「Esc：暂停」，等待主动开始。开始输入只启动倒计时，不同时触发跳跃。
4. 3、2、1 后开始自动奔跑。角色横坐标基本固定，地面与障碍向左移动，产生前进感。
5. 碰撞后立即停止计分，角色短暂后仰，显示本局距离、历史最佳、「再跑一次」「返回桌宠」。
6. 返回时关闭游戏窗口，恢复宠物原位置、大小和原动画暂停偏好，不强制唤起主搜索窗口。

## 3. 画面和操作

- 使用薄荷绿点缀、柔和地面线、半透明深色底板，保证复杂桌面背景下仍能看清障碍。跑道区域边界可见。
- 默认尺寸约 800 × 240 DIP；按工作区缩小，四边保留至少 16 DIP。采用固定逻辑画布等比例缩放，窄屏不缩短障碍预警距离。极小工作区无法保持可读时拒绝开始并保留原宠物。
- 默认位于宠物显示器底部。HUD、左右和底部空白边距可以拖动，按钮和实际跑道不作为拖动区。点按 HUD 不起跳、不暂停；移动超过 4 DIP 后以 `drag` 来源暂停，释放后正常倒计时继续。
- 使用 pointer capture + 具名 `desktop-pet-runner:drag` IPC，主进程校验 sender/mainFrame 与坐标并移动当前窗口。与桌宠相同，由宿主负责移动、夹取和保存；跑道采用页面屏幕坐标而非宠物的系统光标轮询。不使用 CSS 原生拖动区，避免 Windows 原生移窗模态循环，且能够用 Playwright 真实指针验证点击与拖动的区别。
- 释放后完整夹取当前显示器 workArea，显示器变化夹取当前位置而非重新居中。设备键 `desktop-pet-runner-position` 保存 `{version:1,x,y}`，显式 device 路由；只接受有限安全整数 DIP、±1,000,000 坐标。仅恢复仍完整适配已连接 workArea 的位置，否则回落 `runnerBounds`；位置读写失败不阻断游戏。
- 空格、↑ 或按住跑道起跳，释放截断上升速度；忽略键盘重复，仅落地后可再跳。↓ / S 持续下蹲，空中按下快速落地。
- 按钮消费点击，不冒泡触发跳跃。游戏窗口中的双击不执行桌宠的双击指令；拖入文件不触发原文件转发行为。
- Esc 切换到暂停；暂停层提供「继续」「重新开始」「返回桌宠」。继续前短倒计时，防止立刻撞上障碍。
- 切换到其他应用、窗口失去焦点、系统挂起时自动暂停。焦点回来仍保持暂停，需要用户继续。
- × 一键返回桌宠。只有当前窗口获得焦点时处理游戏按键，不注册全局空格热键。
- 首版无音效，减少对工作环境的打扰。

## 4. 玩法与难度

按存活运行时间分阶段，倒计时和暂停不推进难度。

| 等级       | 时间    | 速度 px/s                  | 新解锁                          | 反应余量   |
| ---------- | ------- | -------------------------- | ------------------------------- | ---------- |
| LV1 热身   | 0–20s   | 240→280                    | 石块 36×28、小仙人掌 25×36      | 0.50s      |
| LV2 加速   | 20–45s  | 280→320                    | 高仙人掌 25×60、双仙人掌 58×42  | 0.40s      |
| LV3 飞行物 | 45–75s  | 320→360                    | 低鸟 34×20、中鸟 38×20          | 0.32s      |
| LV4 组合   | 75–110s | 360→400                    | 短/长组合、额外快 65px/s 的滚石 | 0.26s      |
| LV5 极限   | 110s+   | 巡航 400→435，冲刺最高 460 | 全部混合、短冲刺                | 0.22s 下限 |

固定逻辑画布 800×240，地面 y=194，角色 x=114。重力 1800，长跳初速度 -580，释放速度上限 -360；长按最高约 91px、滞空约 0.64s，极短点按最高约 34px、滞空约 0.40s。空中下蹲使速度至少向下 240，并使用 2.5 倍重力。下蹲过渡 0.06s。

身体碰撞宽 30、高 50，脚底留 5px 容错；下蹲身体和素材均整体等比缩放 0.7（高 35），禁止竖向挤压。图格宽高与动画行从 manifest 读取，目标偏移集中在 `SPRITE_DESTINATION`，保留并发素材更新的脚底基线。

低鸟底面离地 12px，必须跳；中鸟底面离地 44px，站姿撞到头顶，下蹲净空。两帧翅膀用 elapsed 驱动，不改变碰撞盒；向下帧不越过身体底面，避免误导下蹲。短组合两块石头各宽 22、高 18、内部净空 14，总宽 58，可短跳；长组合高 30、内部净空 48，总宽 92，需要长跳。组合作为整体排距。

LV5 每 18s 的第 10–11.5s 显示「冲刺将至」，11.5–13.5s 临时加速 35px/s，仍封顶 460。巡航在 140s 达 435，给之后的冲刺保留真实提速空间，避免达到 460 后只剩空提示。HUD 常驻等级，进入阶段的前 2.2s 显示「LV n · 名称」，天色随 0–140s 渐暗。

生成器估计旧模式最后一块清空站姿左边缘的保守时间，再加完整长跳恢复、下蹲过渡和阶段反应余量。按当前速度、滚石相对速度、最大加速率 2px/s²（位移额外 `horizon²`）和 LV5 35px/s 冲刺预算换算空间下限；冲刺结束时旧模式清空速度取减去冲刺的下界，避免后继滚石追上旧模式。不是全局最高速度固定排距。首次生成等待 2s，附加随机间隙逐阶段减小。

单模式净空窗口大于横向交叉时间：最宽长组合在最低解锁速度 360 时需要约 0.32s，低于长跳对 30px 障碍的净空窗口。模式间始终保留一次长跳、下蹲过渡和至少 0.22s 反应余量。20 个种子分别固定步运行 300s 的机器人见证测试，仅发送真实跳跃/下蹲输入，不改物理、不删除障碍或开启无敌；另验证相同种子和输入可精确回放。这是生成策略的长期通过性证据，不是穷尽玩家所有输入。

首版不包含排行榜、奖励商城、养成数值、云同步、联机和其他游戏模式。

## 5. 已核实的接入基础

- `src/main/core/floatingBallManager.ts` 创建透明置顶宠物窗口，配置为 `focusable: false`，并使用 `showInactive()`；不能直接假定其能接收键盘跳跃。
- `src/renderer/src/desktopPet/main.ts` 已有 Canvas 绘制、静态待机、眼睛偏移、拖动跑步和点击手势。
- `src/renderer/src/desktopPet/assets/manifest.json` 已有 idle、running-right、running-left、waving；目前没有跳跃和碰撞动作。
- `src/preload/desktop-pet.ts` 使用隔离桥接，游戏继续采用同样的最小权限原则。
- `electron.vite.config.ts` 已有多个 renderer/preload 入口，可以增加游戏页面。
- `storageRouting.ts` 目前将普通 `ZTOOLS/` 主机键路由至设备库；游戏最佳记录应显式登记为设备数据，并通过现有数据库路由读写。

2026-10-19 的旧桌宠设计文档包含较早的待机循环描述。本提案以当前源码的静态待机行为为基准。

## 6. 技术方案

选择独立、按需创建的游戏 BrowserWindow，原宠物窗口暂时隐藏。游戏准备完成前保留宠物；开始失败则销毁游戏窗口并保留桌宠入口。这样可将游戏键盘输入、矩形跑道交互和宠物的透明命中、拖动操作分开。

游戏窗口使用可聚焦、无边框、跳过任务栏、不可调整尺寸的局部窗口；不用全屏透明覆盖层。窗口范围内接收点击，范围外由其他应用正常接收。仅用户主动开始时获取焦点，失焦后停止模拟，不持续抢焦点。Windows 先验收，macOS/Linux 行为单独验证。

职责分工：

| 拟新增/修改文件                                                        | 职责                                                       |
| ---------------------------------------------------------------------- | ---------------------------------------------------------- |
| `src/main/core/desktopPet/runnerGameManager.ts`                        | 单实例会话、游戏窗口、退出清理、挂起及屏幕变化处理         |
| `src/main/core/floatingBallManager.ts`                                 | 右键入口、游戏期间隐藏、按最新启用状态恢复；清理时结束游戏 |
| `src/shared/desktopPetRunnerTypes.ts`                                  | 游戏状态、受控桥接接口、结果和持久化类型                   |
| `src/preload/desktop-pet-runner.ts`                                    | 就绪、结束、最佳记录、宿主暂停通知等具名接口               |
| `src/renderer/desktop-pet-runner.html`                                 | 独立游戏页面入口                                           |
| `src/renderer/src/desktopPet/runner/engine.ts`                         | 无 DOM 的固定步长物理、障碍生成、碰撞及分数计算            |
| `src/renderer/src/desktopPet/runner/main.ts`                           | 输入、Canvas 渲染、DOM 按钮与状态层、资源释放              |
| `src/renderer/src/desktopPet/runner/style.css`                         | 跑道和控制层样式                                           |
| `electron.vite.config.ts`                                              | 新 renderer/preload 构建入口                               |
| `src/shared/storageKeys.ts`、`src/main/core/storage/storageRouting.ts` | 登记游戏记录设备键及归属                                   |

复用现有跑步图集和播放器逻辑。暂不修改宠物素材协议来强加 jumping/hurt 动作；正式补素材作为后续独立优化。

运行时状态：`ready → countdown → running → gameOver`；countdown/running 均可进入 `paused`，继续经倒计时返回 running；任意状态可退出。该状态不写入 `DesktopPetConfig.mode`，也不改变持久化的 `paused` 偏好。

物理采用固定 1/120 秒步长，渲染使用 requestAnimationFrame。遇到异常长帧进入暂停，避免休眠恢复后一次跨过多个障碍；暂停后清空累计时间和按键状态。暂停与待机画面不持续重绘。纯引擎支持注入随机数源，测试可以稳定复现。

游戏物理不通过 IPC 传每帧位置；只有显式拖动手势发送受限坐标，不向页面暴露任意通道或文件能力。主进程校验游戏窗口发送者和结果类型、有限数值、合理上限；本地最佳记录不宣称防作弊。默认只在产生新纪录时写入设备库，采用版本化记录 `{ version: 1, bestDistance: number }`。写入失败保留结算画面并提示“纪录未保存”，允许正常退出。

## 7. 退出与异常恢复

- 游戏会话只允许一个；重复入口激活已有窗口，不重复开局。
- 原窗口隐藏时停止其光标/命中采样；游戏关闭或渲染进程崩溃后统一释放监听、窗口和会话引用。
- 恢复时检查桌宠当前是否仍启用：用户在设置里关闭桌宠则结束游戏且不重新显示；不把游戏临时隐藏写成持久化关闭。
- 设置中的尺寸/暂停偏好变动以最新配置为准；恢复位置限制在仍存在的工作区内。
- 显示器移除或 DPI/工作区变化时暂停，将跑道重新放入有效工作区，用户确认继续。
- 应用退出时结束会话，不再创建或显示宠物窗口。游戏窗口不能沿用宠物“拦截关闭后隐藏”的处理。
- 加载失败、游戏崩溃均可返回桌宠；不将游戏页失败永久标记为宠物素材损坏。

## 8. 建议实施顺序与验收

1. 窗口和会话：右键进入、准备界面、退出恢复、失败回滚，先确认焦点和鼠标行为。
2. 游戏闭环：跑步、跳跃、单类障碍、碰撞、再来一次；使用纯引擎测试固定步长与碰撞。
3. 完整首版：第二类障碍、渐进难度、暂停恢复、最佳纪录、窄屏适配。
4. 回归与实机验收：普通桌宠的单双击、拖动、文件拖入、静态待机和凝视不退化。

计划验证：

- `tests/renderer/desktopPetRunnerEngine.test.ts`：阶段边界/速度、解锁顺序、点按/长按最高点、站/蹲中鸟碰撞、空中快落、暂停、20 种子×300s 真实碰撞生存与精确回放。
- `tests/main/desktopPetRunnerGeometry.test.ts`：四边夹取、负坐标、小屏缩放、设备位置防御性解析、完整恢复/移除屏幕/不适配回落。
- 截图测试时钟仅非打包窗口且 `ZTOOLS_E2E=1`、`ZTOOLS_E2E_RUNNER_CLOCK=1` 同时启用。普通窗口不暴露 `runnerTest`。快进使用真实固定步与可选输入机器人；进入 LV3 后固定鸟位置仅用于视觉截图，不能用于公平性证明。
- `tests/main/desktopPetRunnerSession.test.ts`：重复开始、加载失败、崩溃恢复、关闭桌宠、应用退出和设备记录写入失败。
- `tests/e2e/desktop-pet-runner.spec.ts`：真实页面输入开始/跳跃/暂停/重开，失焦自动暂停，返回后原宠物可用，重启后最佳记录存在。
- 运行 `pnpm test` 的对应专项、`pnpm typecheck`、`pnpm test:e2e tests/e2e/desktop-pet-runner.spec.ts tests/e2e/desktop-pet.spec.ts`。E2E 沿用临时数据与旧数据目录、源码 Electron 和设置开发服务器，不打包，不访问真实用户数据。
- 跑道截图等待角色、地面及操作提示稳定出现后，只截游戏窗口可见区，输出到 `test-results/playwright`。设置插件相关截图直接截其 WebContentsView。
- Windows 实机另验：窗口焦点、任务栏上方布局、点击边界、125%/150% DPI、多显示器、休眠恢复和正常游戏帧率；自动化测试不能替代这些结论。
