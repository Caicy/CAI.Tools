## 5. 技术实现建议与关键约束

以下为现有方案给出的实现选择，应结合源码落实；它们与上一节已发生的事实不同。

### 本地运行与兼容

- 暂用产品名 CAI.Tools、App ID `tools.cai.local`，默认数据根 `%USERPROFILE%\.cai-tools`，与原版隔离。
- 保留 LMDB 运行存储和 `window.ztools` API；保留匿名插件市场和自配 AI 提供方。
- 无官方账号时 `getUser` 维持无用户的兼容语义；账号、支付或令牌能力明确不可用，不伪造官方身份或付费权限。
- 删除所有可达的官方鉴权、云同步、活动心跳和原版下载安装链路。需检查启动链及 `src/main/api/plugin/internal.ts`，避免仅清理 UI 或单个入口。

### Git 目录与数据边界

- 同步目录保存稳定 JSON、插件原始 `.zpx` 包和明确适配的附件；本机运行数据库、路径、凭据、缓存、会话及未适配数据不写入目录。
- 优先通过已验证的字段白名单投影拆分通用数据和凭据；不通用导出全部 `PLUGIN/` 或运行插件目录。
- JSON 对象键稳定排序，数组顺序保持；按逻辑对象拆文件，避免无意义 Git 差异。删除采用明确协议，不能把拉取中的暂时缺文件当作用户删除。
- 插件版本或结构未知时暂停该插件数据同步；不可静默放宽白名单。
- code-snippets 的复制计数等频繁统计留本机；插件中的任意自由文本仍属于用户内容，粘贴进去的秘密不能承诺自动识别并排除。凭据隔离保证针对已适配的配置字段。
- ZTools 不执行 Git 提交、推送、拉取或冲突修复，也不保存 Git 登录凭据；如需读 Git 状态，使用受限只读命令和参数数组。
- 未配置同步目录、Git 不可用或目录临时失联，仍能本地使用并保留待同步修改。

### 并发与恢复

- 同步变化与业务写入同事务记录到本机 journal；不能仅依赖现有异步 change 事件。现有 storageRouter 事件只覆盖部分数据库，直接使用会漏掉设置。
- 文件监听不能消除外部 Git 写入竞争。用内容哈希、稳定快照、Git 对象及 base/local/incoming 三方比较保护数据；不确定或冲突时停止覆盖并保留本机修改。
- 运行中共享文件变化后暂停导出、提示重启；单纯 add/commit 且共享内容未变，不应要求重启。
- 启动导入需在 LMDB 与业务单例初始化前校验；构造新的本机数据代次并原子切换，旧代次用于失败恢复。
- 成功接受新代次并开始用户编辑后，普通崩溃应保留当前代次和 journal，不能回退丢失后续编辑。
- 计划 A 的自身数据到计划 B 的代次布局需要保留；“不迁移原版数据”不意味着可以丢掉用户在 A 阶段产生的数据。
