# Windows 右键菜单管理

搜索「右键菜单管理」「Windows 右键菜单」或「Context Menu」，打开独立内置插件。插件位于 `internal-plugins/windows-context-menu`，与设置插件分开加载，不再向设置侧栏添加页面。

## 管理范围

| 类型       | 来源                                                                                        | 可设状态                | 修改方式                                           |
| ---------- | ------------------------------------------------------------------------------------------- | ----------------------- | -------------------------------------------------- |
| 菜单命令   | HKCU/HKLM `Software\Classes\<位置>\shell\<名称>`                                            | 显示 / 仅 Shift / 禁用  | `LegacyDisable`、`Extended` 空字符串标记           |
| Shell 扩展 | HKCU/HKLM `Software\Classes\<位置>\shellex\ContextMenuHandlers`，按 CLSID 聚合为一项        | 显示 / 禁用             | 当前用户 `Shell Extensions\Blocked` 中写入该 CLSID |
| 新式菜单   | Windows 11 打包应用 `AppxManifest.xml` 的 `windows.fileExplorerContextMenus`，按 CLSID 聚合 | 显示 / 禁用             | 同上                                               |
| 经典菜单   | HKCU `Software\Classes\CLSID\{86ca1aa0-34aa-4e8b-a509-50c905bae2a2}\InprocServer32`         | 开启 / 关闭（仅 Win11） | 创建或删除该项；存在其他值或子项时拒绝修改         |

位置包括所有文件、文件和文件夹、文件夹（含库等虚拟文件夹）、文件夹、文件夹空白处、磁盘、桌面空白处。列表按所属程序分组（由命令、DLL 的版本信息或包名推断），可按类型、位置、状态、来源（第三方/系统组件）筛选，按名称、程序、命令或注册表路径搜索。`%SystemRoot%` 下的程序标记为系统组件并排在最后。

Shell 扩展与新式菜单只写入当前用户的屏蔽列表，不需要管理员权限，也不改动软件自身的注册项；同一 CLSID 在所有位置同时生效。启用一个被所有用户（HKLM）屏蔽列表屏蔽的项，或修改 HKLM 菜单命令，需要以管理员身份运行应用；未提权时这些项只读。工具不会自动提权。

## 批量操作

- 勾选单项、整组或「全选当前结果」后，可批量禁用、设为仅 Shift 显示或显示。全选不包含系统组件和当前权限下只读的项；系统组件需显式筛选或逐项勾选。
- 不支持目标状态的项（如扩展不支持「仅 Shift」）和已处于目标状态的项会被跳过，确认框中说明跳过数量。
- 整批在一个 PowerShell 进程中逐项执行：每项单独备份、记录和回读校验；单项失败会回滚该项已写入的标记并删除其记录，其余项照常完成，界面列出每个失败项及原因。
- 主进程先整批校验参数（标识格式、状态、重复项、最多 200 项），任一项非法则整批拒绝。

## 生效与重启资源管理器

菜单命令的修改通常在下次打开右键菜单时生效；屏蔽列表和经典菜单开关需要重启资源管理器。修改成功后界面提示，可点击「重启资源管理器」：结束全部 `explorer.exe`，等待系统自动重启外壳，5 秒内未出现新进程则手动启动。执行前需确认，因为已打开的文件夹窗口会关闭，正在进行的文件复制可能被中断。

## 备份与修改记录

每次实际变更前：

1. 菜单命令先用 `reg.exe export` 导出完整菜单项，其余类型生成仅包含撤销指令的 `.reg`；均追加把被修改值恢复为修改前状态的指令（原本不存在的值使用删除指令）。
2. 将版本化 `.json` 修改记录与 `.reg` 一同刷新到磁盘；任一步失败均不修改注册表。

备份保存在应用数据目录的 `context-menu-backups`。v2 记录保存操作类型、修改前后状态，以及每个被修改值的修改前后快照（仅支持 `REG_SZ` 和 `REG_DWORD`；原值为其他类型时拒绝修改，以保证可还原）。旧版 v1 禁用记录按等价的 `LegacyDisable` 变更继续读取和还原。

## 还原

- 在「修改记录」中逐条还原，或点击「还原全部」依次还原所有可撤销记录；单条失败不影响其他记录，并逐条报告。
- 还原前检查当前值：等于修改后快照才写回修改前快照；已经等于修改前状态时只校验不写入；被外部修改时停止并保留记录。菜单命令所在项被删除时停止还原，不会重新创建。
- 同一注册表值只能还原最近一次修改（Shell 扩展与新式菜单共享同一 CLSID 屏蔽值时也按此判断）。
- 还原后回读校验，再写入还原时间；如果注册表已恢复但保存记录失败，会明确说明实际结果并允许重试。
- 任一记录损坏时停止新增修改和还原，并显示损坏文件名；`.reg` 备份仍保留，可手动导入。

## 当前限制

不处理特定文件类型（如 `.txt`、`SystemFileAssociations`）专属的菜单命令，以及 32 位独立注册表视图。资源字符串形式的菜单名称显示原始注册表值；新式菜单项显示「包名 · Verb Id」，实际菜单文字由应用运行时提供。启用状态仅表示未设置本工具管理的标记，菜单还可能受 `ProgrammaticAccessOnly` 等标志及系统策略影响。当前用户同名项可能覆盖所有用户项，因此分别显示两个来源。经典菜单开启时新式菜单项不会出现，对它们的修改需切回新式菜单后才能看到。

## 实现说明

注册表读写由固定的 PowerShell 脚本完成（`src/main/utils/windowsContextMenu.ts`）：短引导命令从 stdin 读取 base64 编码的脚本和 JSON 参数，避免命令行长度限制、控制台代码页影响中文以及参数拼接注入。读取时注册表与新式菜单（需扫描 Appx 清单，约数秒）并行执行，新式菜单读取失败只作为警告。

## 验证

- 单元与权限测试：`pnpm exec vitest run tests/main/windowsContextMenu.test.ts tests/main/windowsContextMenuRestore.test.ts tests/main/windowsContextMenuIPC.test.ts`，覆盖标识与参数校验、批量请求构造、读取降级、并发写锁、v1/v2 记录校验与篡改拒绝、跨类型冲突判断、批量还原部分失败及 IPC 鉴权。
- Windows 注册表集成测试：`pnpm exec vitest run tests/main/windowsContextMenu.windows.test.ts`。仅在 Windows 运行；使用唯一命名的 HKCU 测试项、随机 CLSID 和专用的经典菜单测试键，验证三态切换、`.reg` 导入恢复、跨实例逐条还原、外部修改拒绝、批量部分失败、扩展屏蔽及经典菜单开关与还原，最后清理测试项。不会修改真实的经典菜单设置，也不会重启资源管理器。
- 开发模式 Electron E2E：`pnpm test:e2e tests/e2e/windows-context-menu.spec.ts`，使用隔离数据目录，校验真实搜索入口、只读读取真实注册表、IPC 和平台提示。随后替换全部写入接口为示例数据，验证分组排序、只读项、单项取消/确认/失败、批量禁用部分失败、经典菜单开关、重启资源管理器确认及还原全部，并生成明确标注示例数据的截图。
- Windows 手工验证：在 HKCU 的 `Software\Classes\Directory\Background\shell` 创建专用测试项及无害命令，依次设为仅 Shift、禁用并核对备份与标记，再从修改记录还原；对一个第三方 Shell 扩展禁用后重启资源管理器核对菜单消失，还原后再次核对。
- 额外检查：HKLM 权限不足、备份目录不可写、菜单项被外部删除时应展示失败并刷新，不把操作误报为成功。

Linux 下的单元测试及页面构建无法替代 Windows 的真实注册表和资源管理器验证。

## 开发与随包加载

`pnpm dev` 同时启动主程序、设置插件和本插件。单独启动插件可用 `pnpm dev:context-menu`，端口为 `5178`。E2E 使用独立端口 `15178`，通过 `ZTOOLS_CONTEXT_MENU_DEV_SERVER_URL` 指定测试入口，避免占用日常开发服务。本插件使用根项目的 Vue/Vite 依赖，不需要独立安装一份依赖。

`pnpm typecheck:context-menu` 检查独立插件类型；`pnpm build:context-menu` 构建到插件的 `dist`。根项目构建已包含此步骤。内置插件注册表及 `afterPack` 均包含本插件，打包时缺少其构建产物会报错。

注册表 IPC（`internal:context-menu-list/apply/backups/restore/classic/restart-explorer`）仅允许名称、内置标记、源码/安装目录均匹配的内置右键菜单插件主框架调用；设置插件、未知窗口、其他插件、同名外部插件或子框架均拒绝调用。主进程再校验标识、状态和记录内容，变更只能落在受支持的直接 shell 子项或屏蔽列表中对应的 CLSID 上。
